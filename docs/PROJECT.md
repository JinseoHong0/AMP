# AMP — 제품·기능 상세 명세서 (PROJECT.md)

> **Amplify Local Stages. 작은 무대의 울림을 세계로.**  
> 2026 명지대학교 AI × K-콘텐츠 해커톤 · 5조  
> 문서 버전: 1.0 · 상태: **개발 전 제안 명세** · 갱신: 2026-11-05

## 1. 프로젝트 목적

AMP는 신촌·홍대의 인디 라이브 공연을 **찾고, 이해하고, 실제로 방문**하도록 돕는 AI 기반 로컬 공연 큐레이터다. 공급자는 포스터를 업로드해 공연 정보를 신속히 등록한다. 소비자는 자연어 및 필터로 공연을 찾고, 장소별 입장 가이드를 확인한다.

### 핵심 문제
- 공연 정보가 SNS·포스터에 분산되어 있다.
- 첫 방문자는 입구 위치, 층수, 스탠딩/좌석, 드링크 정책을 몰라 망설인다.
- 비한국어 사용자에게는 현장 표현과 문화 맥락의 장벽이 있다.
- 소규모 공연 제공자는 정보 등록·노출이 어렵다.

### 목표 사용자
| 페르소나 | 상황 | AMP가 제공하는 가치 |
|---|---|---|
| 공연 초심자 | 혼자서 저렴한 공연을 보고 싶음 | 자연어 검색, 조건이 맞는 공연, 현장 가이드 |
| 해외 여행객 | 서울 로컬 라이브 공연을 발견하고 싶음 | 영어 입장 안내, 확인된 방문 정보 |
| 공연 제공자 | 포스터만 만들어 놓고 홍보 통로가 부족함 | AI 정보 추출, 검수 후 등록, 검색 DB 반영 |

### 성공 기준(MVP)
1. 자연어+필터로 **실제 DB에 존재하는** 공연을 최대 3개 추천한다.
2. 추천 카드에서 입장 가이드를 열고 EN 토글을 사용할 수 있다.
3. 포스터를 올려 AI가 정보를 추출하고, 사람이 수정·검수한 뒤 등록한다.
4. 등록 직후 공연은 **DB 조회 대상**이 되고, 추천 조건에 부합할 때 검색 결과에 나타난다.
5. 발표용 **90초 시연 흐름**을 끝까지 수행할 수 있다.

## 2. MVP 포함/제외 범위

### 포함(P0, 반드시 완성)
- 메인 자연어 검색 입력창
- 필터 칩: 날짜(오늘/내일/선택 날짜), 지역(신촌/홍대), 가격 상한, 분위기, 혼자 관람 여부
- LLM 기반 검색 의도 추출 및 Pydantic 검증
- DB의 엄격한 필터링 + 결정적 점수 계산(상위 최대 3개)
- 근거가 있는 1줄 추천 사유
- 공연 상세 및 공연장 입장 가이드: 입구 이미지, 위치/층수, 관람 방식, 드링크 정책, 분위기, 동네 이야기
- 한/영 가이드 토글(검수된 영어 텍스트만 사용)
- 포스터 이미지 업로드 → Vision 추출 → 편집 폼 → 등록
- 신규 공연 목록 반영, 빈 검색·오류 화면
- 공연 데이터 출처와 데모 데이터 표시

### 제외(P2, 해커톤 이후)
- 결제/예매, 커뮤니티, 북마크, 주변 관광 코스, 실시간 SNS 크롤링
- 회원가입/소셜 로그인, 자동 번역 파이프라인, 벡터 DB, 매칭 서비스
- 추천 정확도를 학습하는 모델 훈련, 실시간 외부 공연 수집

## 3. 화면별 기능 명세

### S01. 홈/추천 (`/`)
**구성:** AMP 로고, 자연어 입력, 빠른 필터 칩, 추천 버튼, 결과 0~3개 카드, 에러/로딩/빈 상태.

**사용자 흐름**
1. 자연어를 적거나 필터 칩을 조작한다(둘 중 하나 이상 필요).
2. 검색을 누르면 `POST /api/recommend`에 전송한다.
3. 응답이 오면 적용된 필터를 표시하고 최대 3개 카드를 출력한다.
4. 카드에서 상세 화면을 연다.

**추천 카드 필수 정보:** 공연명, 공연 일시(KST), 공연장명/지역, 가격(미확인이면 표시), 분위기 태그, 1줄 이유, 데이터 라벨(`DEMO`/`VERIFIED`).

**완료 조건(Acceptance Criteria)**
- [ ] `오늘`, `2만원 이하`, `신촌`은 서버에서 동일하게 해석된다.
- [ ] 필수 조건에 불일치하는 공연을 추천하지 않는다.
- [ ] 조건 일치 공연이 0건이면 대체 공연을 사실처럼 지어내지 않는다.
- [ ] API 실패 시 재시도 메시지와 기존 입력이 유지된다.
- [ ] 화면에 추천 결과가 최대 3개만 표시된다.

### S02. 공연 상세/입장 가이드 (`/events/:id` 또는 모달)
**필수 항목:** 포스터, 출연진, 공연 일시·가격, 공연장 주소, 입구 이미지(없으면 없음 표시), 층수, 좌석/스탠딩, 드링크 정책, 지역 이야기 2~3줄, 정보 출처/확인일.

**동작:** `GET /api/events/{id}`로 공연, `GET /api/venues/{id}`로 장소 정보를 요청한다. 공연별 `seating_type`, `drink_policy` 값이 있으면 공연장 기본 정책보다 우선 표시한다.

**언어:** `KO/EN` 토글은 검수된 텍스트를 전환한다. 번역이 없으면 원문과 `영문 안내 준비 중` 표시; 실시간 AI 번역으로 확인되지 않은 내용을 보충하지 않는다.

**완료 조건**
- [ ] 공연장 안내를 여러 공연이 재사용한다.
- [ ] 드링크 정책 등 행사별 변동 항목의 덮어쓰기가 적용된다.
- [ ] 사진·정책·확인일이 없는 경우 사실을 만들어내지 않는다.
- [ ] EN 토글이 적어도 주요 입장 안내에서 동작한다.

### S03. 공연 제공자 등록 (`/admin/register`)
**구성:** 포스터 업로드, 추출 진행 상태, 추출 결과 편집 폼, 장소 기존 목록 매칭/선택, 경고 표시, 최종 등록 버튼.

**흐름**
1. `JPG/PNG/WebP`, 최대 5MB 포스터 업로드.
2. `POST /api/posters/parse`로 이미지 전송(`multipart/form-data`).
3. 추출된 제목·일시·장소명·가격·라인업·장르를 폼에 채운다.
4. 확인되지 않은 값은 빈칸과 경고로 표시한다. 사용자가 수정한다.
5. DB에 **이미 존재하는 venue**를 선택해야 등록할 수 있다(MVP에서는 장소 신규 생성 제외).
6. `POST /api/events`로 사용자 검수를 거친 데이터를 저장한다.
7. 저장 성공 시 이벤트 상세 또는 등록 완료 화면으로 이동한다.

**완료 조건**
- [ ] 검수 없이 자동 등록되지 않는다.
- [ ] 가격/날짜 등의 필수 검증이 동작한다(가격은 미확인 `null` 허용).
- [ ] 포스터에 없는 정보는 자동으로 사실을 만들어내지 않는다.
- [ ] 등록한 공연을 목록 조회로 즉시 확인할 수 있다.
- [ ] 잘못된 이미지·API 실패 시 안전하게 재시도할 수 있다.

**권한:** 해커톤에서는 로컬/통제된 데모 환경의 관리자 기능으로 운용한다. 외부 공개 서비스에서는 정상적인 인증·권한 관리 없이는 등록 기능을 노출하지 않는다.

## 4. 추천 정책

| 기준 | 처리 |
|---|---|
| 행사 상태 | `published`만 조회 |
| 지난 공연 | 미래 공연만 추천(시간 기준 `Asia/Seoul`) |
| 날짜 | 사용자가 요청한 현지 일자와 일치해야 함(하드 필터) |
| 지역 | `sinchon`, `hongdae` 등 정규화한 코드로 비교(하드 필터) |
| 가격 | 상한 적용 시 `price_krw <= max_price_krw`; 미확인 가격은 제외 |
| 분위기 | 해당하는 검수된 태그에 가중치 부여(소프트 랭킹) |
| 혼자 방문 | 검수된 `solo_friendly=true`에 가중치 부여; `null`은 미확인 |
| 동점 | 시작 일시 오름차순, 행사 ID 오름차순(결정적 정렬) |

**LLM 역할:** 자연어 → 검색 조건 파싱, 선택된 이벤트의 검증 가능한 속성에 한정한 이유 생성. **LLM이 DB에 없는 공연을 새로 추천하도록 허용하지 않는다.** 추천 문장은 안전한 템플릿으로 대체할 수 있어야 한다.

**필터 우선순위:** 사용자가 직접 선택한 UI 필터 칩이 자연어에서 추출된 값보다 우선한다. 충돌은 `applied_filters`에 반영한다.

## 5. 데이터 운영 원칙

- 초기 목표: **공연 20건 이상, 공연장 4곳 이상**. 데모 검색 조건에 일치하는 공연이 3건 이상 존재하도록 픽스처 설계.
- 실제 데이터는 공개 출처·확인 시각·권리(사진/포스터)를 확인한다.
- 합성 데이터는 반드시 `data_origin=demo`로 저장하고 화면에 `DEMO` 표시한다.
- 미확인 가격은 `null`, 무료는 `0`; 둘을 혼동하지 않는다.
- 실시간 크롤링은 하지 않는다. 공연 정보의 유효성을 새로 갱신할 책임이 있다.
- 앱·DB는 UTC로 시각을 저장하고, 한국 공연일자/표시는 `Asia/Seoul`로 변환한다.
- 정보 수집 및 이미지 사용은 해당 출처의 정책과 저작권을 존중한다.

## 6. 비기능 요구사항

- **성능 목표(측정 전 약속하지 않음):** 목록·가이드 API는 로컬 환경 p95 1초 이내 지향. LLM API 응답은 공급자와 네트워크 상태에 따라 달라질 수 있음.
- **실패 복구:** 추천 LLM 실패 시 칩 기반 검색 또는 명시적 오류; 설명 생성 실패 시 사실 기반 템플릿; Vision 실패 시 수동 입력으로 진행.
- **보안:** API 키는 백엔드 환경변수에만 둔다. 업로드 MIME+시그니처/크기 검사, 랜덤 파일명, CORS 허용 출처 제한.
- **접근성:** 키보드로 검색·가이드·언어 토글 가능; 사진에는 대체 텍스트.
- **배포:** 로컬 시연 우선. 공개 웹 배포 시 React는 Vercel 가능, FastAPI는 영구 디스크/DB 호스팅을 사용. 서버리스 로컬 SQLite에 의존하지 않는다.
- **기록:** API 오류 코드·시간·요청 ID는 로그로 남기되 API 키와 원본 개인 데이터는 기록하지 않는다.

## 7. 90초 데모 및 수용 시나리오

1. 사용자가 `신촌에서 오늘 2만원 이하 잔잔한 공연`을 검색한다.
2. 실제 데이터(또는 DEMO 라벨이 있는 픽스처)에서 최대 3개 추천하고 한 줄 근거를 보여준다.
3. 카드 클릭 → 입구 사진, 층수, 관람 정책 확인 → 영어 토글.
4. 관리자 화면에서 **사전에 검증한 샘플 포스터** 업로드 → 추출·수정·등록.
5. **같은 조건을 만족하도록 준비한** 신규 공연이 목록과 적절한 추천 결과에 나타난다.
6. 실패 시 재시도 또는 백업 영상으로 회복한다.

> 데모에서 신규 등록 공연을 노출하기 위해 추천 규칙을 예외 처리하거나 다른 공연을 숨기지 않는다. 데이터와 검색 조건을 합법적으로 맞춘다.
