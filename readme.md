> **Amplify Local Stages.**

## 1. 프로젝트 소개 (Overview)

### 🎵 What is AMP?

**AMP**는 서울 신촌·홍대 지역의 인디 라이브 클럽과 소규모 공연을 쉽게 발견하고 방문할 수 있도록 돕는 AI 기반 공연 큐레이션 서비스입니다.

기타 앰프(Amplifier)가 작은 소리를 증폭해 더 많은 사람에게 전달하듯, AMP는 작은 공연장의 목소리를 더 크게 전달하고 밴드와 관객, 서울의 로컬 문화와 세계를 연결합니다.

**"공연 정보는 존재한다. AMP는 그 정보가 나에게 맞는 선택과 실제 방문으로 이어지도록 돕는다."**

### 🎯 문제 정의 (Problem)

기존에도 공연 정보를 모아서 제공하는 서비스(예: 인디스트릿)가 있습니다. 따라서 AMP는 **"공연 정보가 전혀 없다"**는 전제보다, **"정보를 발견한 뒤 나에게 맞는 공연을 선택하고 실제 방문을 준비하기까지 여전히 여러 단계가 필요하다"**는 문제에 집중합니다.

**관객의 문제**
- 공연 목록을 찾더라도 일정·예산·취향·관람 방식에 맞는 후보를 일일이 비교해야 합니다.
- 입장 시간, 층수, 좌석 방식, 드링크 정책 등 중요한 정보가 공연별 긴 안내문 속에 섞여 있을 수 있습니다.
- 혼자 방문하거나 처음 라이브 클럽에 가는 관객은 현장에서 무엇을 확인해야 하는지 판단하기 어렵습니다.
- 외국인 방문객은 다국어 메뉴가 있더라도 한국어로 작성된 개별 공연 공지와 로컬 관람 규칙을 이해하기 어려울 수 있습니다.

**공연 제공자의 문제**
- 공연 정보 등록 과정에서 제목·일시·가격·출연진·공연장 등을 확인하고 반복 입력해야 할 수 있습니다.
- 포스터만 준비된 경우, 그 내용을 별도의 등록 양식에 옮기는 작업이 필요합니다.
- 기존 공연장 DB와 연결해야 하는 경우 공연장을 직접 찾아 선택해야 합니다.

### 🔎 기존 서비스와의 관계 (Competitive Positioning)

직접 확인한 인디스트릿의 공연 등록 흐름에서는 **텍스트 입력 후 날짜·가격·아티스트(해시태그 등)를 자동 추출**할 수 있습니다. 공연장은 기존 DB에서 직접 선택해야 하며, 해당 등록 화면에서 공연장 선택은 필수 입력 항목이 아닙니다. 포스터 이미지는 첨부할 수 있지만, **포스터 이미지에서 자동으로 입력값을 추출하는 기능의 제공 여부는 확인되지 않았습니다.**

| 구분 | 기존 서비스에서 확인한 기능 | AMP가 집중할 개선 경험 |
|---|---|---|
| 공연 정보 | 일정·가격·출연진·공연장·예매 등 기본 정보 제공 | 내 상황에 맞는 후보 선택과 추천 이유 |
| 방문 안내 | 일부 공연에 입장·층수·좌석 등의 상세 문구 존재 | 핵심 사실을 별도 방문 준비 카드로 구조화 |
| 다국어 | 다국어 메뉴 제공 | 공연별 실제 방문 안내를 한국어·영어로 명확히 제공 |
| 공연 등록 | 직접 입력 + 텍스트 정보 자동 추출 | **포스터 이미지**에서 추출하고 기존 공연장 DB에 매칭 |

> **검증 원칙:** 위 표는 현재까지 확인된 범위만 비교합니다. 기존 서비스에 자연어 추천·이미지 추출·초심자 가이드가 **없다고 단정하지 않습니다.** AMP가 더 빠르거나 편리하다는 주장도 실제 비교 실험 전에는 확정하지 않습니다.

### 🌏 Local to Global

서울의 인디 공연 문화는 해외 여행객도 경험할 수 있는 로컬 K-콘텐츠입니다.

AMP는 **Discover → Decide → Visit**의 관객 여정을 중심으로 공연을 추천하고, 방문에 꼭 필요한 정보를 구조화해 한국어·영어로 안내합니다. 공급자에게는 포스터 이미지 기반 등록 흐름을 제공하여 공연 정보가 관객에게 연결되는 과정을 단순화합니다.

## 2. 핵심 기능 (Core Features)

### ① AI 상황 맞춤형 공연 추천 — Discover & Decide

사용자가 자연어로 원하는 공연을 설명하면 AI가 **DB 조회 도구를 직접 호출**하고, 결과를 읽어 필요한 재조회와 추천을 수행합니다. 추천 결과에는 **왜 이 공연이 적합한지** 확인 가능한 근거를 함께 표시합니다.

**검색 예시**

> "오늘 홍대에서 혼자 갈 만한 2만 원 이하 공연 추천해 줘. 스탠딩은 별로야."

**추천 프로세스**
1. 사용자 자연어 입력
2. AI가 원문과 UI 필터에서 의도를 파악하고 조회 조건·도구 호출을 결정
3. 서버가 DB 조회 도구를 실행하고 실제 후보와 설명·가격·좌석 등 근거를 AI에 반환
4. AI가 결과를 비교하고 필요한 경우 조건·키워드·페이지를 바꿔 재조회(사용자의 필수 조건 유지)
5. AI가 최대 3개와 추천 이유를 선택하고, 서버가 ID·조건·근거를 검증해 반환

**핵심 원칙**
- DB에 없는 공연을 추천하거나 정보가 불확실한 공연을 지어내지 않습니다.
- **필수 조건과 선호 조건을 구분**합니다. 예를 들어 "스탠딩은 안 돼"는 제외 조건이며, 단순히 "좌석을 선호해"는 선호 조건입니다.
- 공연의 좌석 방식·분위기·혼자 방문 적합성을 확인하지 못했다면 사실인 것처럼 설명하지 않습니다.
- 예매가와 현장가가 다르면 가격 조건을 만족하는 **구매 방식**을 함께 표시합니다(예: "예매 시 20,000원").
- 일치하는 공연이 없거나 필수 정보가 부족한 경우 이를 명확히 안내합니다.
- 날짜·시간은 **Asia/Seoul** 기준으로 처리합니다.

### ② 방문 준비 카드 & Global Toggle — Visit

기존 공연 안내문에 존재하는 정보를 **처음 방문하는 관객이 바로 행동할 수 있는 형태**로 구조화합니다. 공연 상세 화면에서는 행사별 방문 준비 카드를 우선 보여주고, 필요한 경우 공연장 기본 정보를 함께 제공합니다.

**방문 준비 카드 항목**
- 공연장 이름·주소·건물 층수 및 입구 사진(확보된 경우)
- **공연 시작 시간과 입장 시작 시간 구분**
- 스탠딩 / 좌석 / 비지정석 등 관람 방식
- **예매가 / 현장가** 구분 및 예매 링크(확인된 경우)
- 공연별 드링크 정책·입장 규칙·주의사항
- 한국어 / 영어 핵심 안내 전환

**표시 및 검증 원칙**
- 공연별 규정이 있는 경우 **행사 정보가 공연장 기본 안내보다 우선**합니다.
- 정보가 없으면 "확인 필요 / Not confirmed"로 표시하고, AI가 보완해 만들지 않습니다.
- 공연장 입구 사진, 층수, 규칙은 검증된 자료만 표시합니다. 입구 사진은 확보되지 않아도 서비스가 동작합니다.
- 공연 등록 시 제목·소개·입장 안내·드링크 안내를 영어로 자동 번역해 함께 저장합니다. `AI-translated` 표시와 원문 보기를 제공하고, 원문에 없는 규칙이나 편의시설을 추가하지 않습니다.
- **MVP에서는 검수된 구조화 데이터를 보여주는 것**을 우선 구현하며, 긴 안내문 전체의 AI 자동 구조화는 후속 확장 범위로 둡니다.

### ③ AI 포스터 자동 등록 — Amplify (공급자 기능)

공연 제공자가 **포스터 이미지 한 장을 출발점**으로 등록을 시작하면 Vision LLM이 정보를 추출합니다. 기존 서비스의 텍스트 입력 자동 추출과 구분되는 점은 **이미지 입력 → 기존 공연장 DB 매칭 → 원문 확인 → 영문 자동 생성·저장**까지의 흐름입니다.

**추출 대상**
- 공연명
- 날짜 및 공연 시작 시간
- 포스터에 기재된 공연장 이름
- 티켓 가격(구분이 확인되는 경우 예매가 / 현장가)
- 출연진 / 라인업
- 장르 및 분위기 관련 후보 정보(확인·수정이 필요한 제안값)

**등록 프로세스**
1. 공연 포스터 이미지 업로드
2. Vision LLM으로 이미지 분석 후 구조화된 JSON 반환
3. 추출된 공연장 이름을 **기존 Venues DB와 자동 매칭 시도**
4. 매칭 결과를 화면에 표시하고, 실패 시 사전 등록된 공연장 목록에서 **직접 선택**하도록 안내
5. 제공자가 누락·오인식된 값과 장르·분위기 태그를 확인·수정
6. 최종 원문을 확인하고 등록하면 영어 번역도 자동 생성해 함께 저장
7. 번역 실패 시 공연 등록은 완료하고 번역만 재시도. 신규 공연은 검색·추천에 반영

**MVP 제약**
- 사전 등록된 공연장만 선택할 수 있으며, `venue_id`는 **필수**입니다. 포스터에서 읽은 공연장명이 DB에 없으면 **새 공연장을 AI가 임의 생성하지 않습니다.**
- 공연장 매칭은 정규화된 이름 비교 등 간단한 방식부터 구현합니다. 모호하면 자동 확정하지 않고 사용자 선택으로 넘깁니다.
- 포스터에서 보이지 않는 정보(좌석 정책, 입장 시간 등)는 생성하지 않고 비워 둡니다.
- 공연 원본 정보는 등록자가 확인한 뒤 저장합니다. 영어는 별도 입력·검수 절차 없이 자동 생성하고 자동 번역임을 표시합니다.

## 3. MVP 범위 (Scope)

### ✅ P0 — 관객 핵심 흐름 (먼저 완성)
- 등록된 공연 DB 기반 목록·상세 조회
- AI의 자연어 해석·DB 도구 조회·재조회·후보 비교와 서버 검증
- 최대 3개 추천 카드와 **추천 이유** 표시
- 공연별 **방문 준비 카드**(확인된 정보만 표시)
- 핵심 방문 정보의 **한국어 / 영어 전환**
- 조건 불일치·정보 미확인 시 예외 안내

### ✅ P1 — 공급자 등록 흐름 (최종 시연 범위)
- 포스터 이미지 업로드와 Vision AI 정보 추출
- 기존 공연장 DB 자동 매칭 시도 및 실패 시 수동 선택
- 추출 원문 확인 후 영문 자동 생성·공연 등록 및 번역 실패 시 재시도
- 신규 공연이 목록·검색·추천 DB에 반영되는지 확인

> **우선순위 원칙:** P1도 최종 데모 목표에 포함하지만, 프론트엔드·백엔드 통합에서는 **P0 관객 경험을 먼저 안정화**합니다. P1이 지연되더라도 P0 데모는 독립적으로 작동해야 합니다.

### ❌ Out of Scope
- 아티스트 상세 프로필 관리 및 아티스트/공연장 전체 CRUD
- 신규 공연장 자동 생성 및 대규모 공연장 관리 시스템
- 사용자 커뮤니티, 북마크 및 개인 컬렉션
- 공연 예매 및 결제
- 밴드·세션 멤버 매칭
- 주변 관광 코스 추천
- 실시간 SNS 자동 크롤링·대량 수집
- 긴 비정형 안내문 전체의 AI 자동 구조화

제외된 기능은 필요성이 검증되면 향후 확장 대상으로 검토합니다.

## 4. 기술 스택 (Tech Stack)

| Category | Technology |
|---|---|
| Frontend | React, TypeScript, Vite |
| Styling | Tailwind CSS |
| Backend | Python, FastAPI |
| Data Validation | Pydantic |
| Database | SQLite |
| AI | LLM(검색 계획·DB 도구 호출·추천), Multimodal Vision LLM(포스터 분석) |
| AI Output | Tool calling + Structured JSON |
| Collaboration | Git, GitHub |
| Deployment | Vercel / Backend Hosting (TBD) |

### 기술 선택 이유

**React + TypeScript + Vite**
- 컴포넌트 단위 UI 개발 및 협업
- 빠른 개발 환경 구축
- 검색·상세·등록 화면 분리

**FastAPI**
- Python 기반 AI 모델 및 외부 LLM API 연동
- REST API 개발에 적합
- Pydantic을 통한 입력 데이터 검증
- 자동 API 문서 제공

**SQLite**
- 별도 DB 서버 구축 불필요
- 소규모 해커톤 데이터 관리에 적합
- 신규 공연 등록 및 검색 결과 반영 가능

## 5. 시스템 아키텍처 (Architecture)

```text
                ┌─────────────────────┐
                │       User          │
                └──────────┬──────────┘
                           │
                           ▼
                ┌─────────────────────┐
                │ React + TypeScript  │
                │      Frontend       │
                └──────────┬──────────┘
                           │ REST API
                           ▼
                ┌─────────────────────┐
                │  Python FastAPI     │
                │      Backend        │
                └──────────┬──────────┘
                           │
            ┌──────────────┼──────────────┐
            │              │              │
            ▼              ▼              ▼
     AI Recommendation  Venue Guide   Poster Parser
            │              │              │
            ▼              │              ▼
      LLM + DB Tools       │          Vision LLM
            │              │              │
            └──────────────┼──────────────┘
                           │
                           ▼
                ┌─────────────────────┐
                │   SQLite Database   │
                │   Events / Venues   │
                └─────────────────────┘
```

**처리 책임:** AI가 검색 계획·DB 조회 도구 호출·재조회·후보 비교·추천 이유를 담당합니다. FastAPI는 읽기 전용 도구를 실행하고, 필수 조건 유지와 실제 공연 ID·근거를 검증합니다. 고정 가중치 추천은 사용하지 않습니다. 포스터 추출 후 공연장 이름 매칭은 기존 서버 로직을 유지하며, 검색용 쓰기 도구는 제공하지 않습니다.

## 6. 데이터 구조 (Database)

기존 `Events`·`Venues` 테이블과 주요 필드명을 유지하고, 방문 안내와 등록 검수에 필요한 항목만 **선택적으로 추가**합니다. 새 필드는 기존 클라이언트 호환성을 고려해 기본적으로 nullable 또는 선택값으로 설계합니다(단, 아래 `venue_id`는 MVP 등록 필수).

### Events — 공연 정보

| Field | Description |
|---|---|
| id | 공연 고유 ID |
| venue_id | 공연장 ID (**MVP 신규 등록 시 필수; Venues 참조**) |
| title / title_en | 원문 공연명 / 등록 시 자동 생성 영문 |
| translation_status | 번역 상태: not_requested / generated / failed / reviewed |
| starts_at | 공연 시작 일시 (Asia/Seoul 기준 처리) |
| price | 기존 검색·표시용 대표 티켓 가격(실제 유효한 가격 기준; 가격 조건 명시) |
| genre | 음악 장르(검수된 값) |
| mood_tags | 분위기 태그(검수된 값) |
| lineup | 출연진 |
| seating_type | 해당 공연의 스탠딩·좌석·비지정석 등 관람 방식 |
| drink_policy / drink_policy_en | 해당 공연의 드링크 정책 원문 / 자동 번역 |
| poster_url | 포스터 이미지 |
| source_url | 공연 정보 확인 출처 |
| **doors_open_at** | **[추가·선택] 공연별 입장 시작 일시** |
| **advance_price** | **[추가·선택] 예매가** |
| **door_price** | **[추가·선택] 현장가** |
| **booking_url** | **[추가·선택] 예매 링크** |
| **admission_notes_ko** | **[추가·선택] 공연별 한국어 입장·관람 안내** |
| **admission_notes_en** | **[자동 생성] 한국어 원문에서 번역한 영어 입장 안내** |
| **verified_at** | **[추가·선택] 공연별 정보 확인 일시** |

### Venues — 공연장 정보

| Field | Description |
|---|---|
| id | 공연장 고유 ID |
| name | 공연장명 |
| area | 지역 |
| address | 주소 |
| floor | 층수 |
| entrance_image | 입구 이미지(확보된 경우) |
| entrance_hint_ko | 공연장 입구·동선 한국어 안내 |
| **entrance_hint_en** | **사전에 준비된 공연장 입구·동선 영어 안내** |
| source_url | 정보 확인 출처 |
| verified_at | 정보 최종 확인 일시 |

**데이터 처리 규칙**
- **공연별 `seating_type`·`drink_policy`·`doors_open_at`·`admission_notes_*` 정보가 있으면 우선 적용**하고, 공연장 기본 안내는 보조 정보로 제공합니다.
- 가격이 여러 개라면 `advance_price`·`door_price`를 구분하고, `price`를 검색 기준으로 사용할 때 **어떤 구매 방식의 가격인지** 명확히 표시합니다. 가격이 검증되지 않으면 임의로 0원 처리하지 않습니다.
- 확인되지 않은 값은 `null`로 저장하고, 화면에 "확인 필요"로 표시합니다.
- 초기 시드 데이터는 **공연 약 20건 / 공연장 4~5곳**을 목표로 하며, 검증된 실제 정보와 시연용 가상 데이터를 구분합니다.
- 외부 공연 정보 및 이미지 사용 시 출처와 이용 조건을 확인합니다. **공개된 웹페이지에 있다는 이유만으로 무단 복제·크롤링하지 않습니다.**

## 7. API 설계 (API Endpoints)

기존 API 경로를 유지하며 공연장 수동 선택 조회와 **등록된 공연의 번역 재시도 API**를 제공합니다.

| Method | Endpoint | Description |
|---|---|---|
| POST | `/api/recommend` | AI DB 조회·재조회 → 후보 비교 → 검증된 최대 3개 추천 |
| GET | `/api/events` | 공연 목록 조회 |
| GET | `/api/events/{id}` | 공연 상세·방문 준비 정보 조회 |
| **GET** | **`/api/venues`** | **[추가] 사전 등록 공연장 목록 / 이름 검색(매칭 실패 시 선택용)** |
| GET | `/api/venues/{id}` | 공연장 기본 입장 가이드 조회 |
| POST | `/api/posters/parse` | 포스터 이미지에서 정보 추출 + 공연장 DB 매칭 시도 |
| POST | `/api/events` | 원문 확인 후 영어 자동 생성·공연 등록 (`venue_id` 필수) |
| POST | `/api/events/{id}/translate` | 저장된 원문으로 영어 번역 재시도(관리자 전용) |
| GET | `/api/health` | 서버 상태 확인 |

**API 응답 및 검수 원칙**
- `POST /api/recommend`: DB에 존재하는 공연만 반환하며, 각 추천에는 확인 가능한 추천 이유를 포함합니다. 결과가 없으면 빈 목록과 안내 메시지를 반환합니다.
- `POST /api/posters/parse`: 기존 추출 필드를 유지하되, `venue_name_detected`와 매칭된 `venue_id`(없으면 `null`)를 함께 반환하도록 확장합니다. 자동 매칭이 불확실하면 확정값을 반환하지 않습니다.
- `GET /api/venues`: 수동 선택을 위한 간단한 목록 조회입니다. 별도 공연장 등록 API는 MVP에 포함하지 않습니다.
- `POST /api/events`: 최종 확인한 원문을 검증하고 영어를 자동 생성해 저장합니다. 번역만 실패하면 원문 등록은 성공하며 번역 재시도를 제공합니다. `venue_id`가 없거나 필수 필드가 누락되면 저장을 거부합니다.
- 새 응답 필드는 기존 타입에 **선택 속성으로 추가**하여 프론트엔드 변경 범위를 최소화합니다. 세부 요청·응답 JSON 형식은 `docs/API.md`에서 프론트엔드·백엔드가 함께 확정합니다.

## 변경 이력 (README v1.1)

- **등록 번역 확장:** 한국어 등록 시 영어 자동 생성·저장, 자동 번역 표시·원문 보기, 번역 실패 분리·재시도 추가

- **검색 설계 개정:** AI가 DB 도구를 호출하고 후보를 비교·추천하는 흐름으로 변경. 문장 판단표·고정 점수 제거, 조회 제한·조건 유지·확인 질문·실패 처리 명시

- **문제 정의 변경:** 정보 부재 중심 → 공연 선택·방문 준비·등록 수작업의 마찰 중심
- **경쟁 서비스 조사 반영:** 인디스트릿과 겹치는 기능을 인정하고, 미확인 기능은 단정하지 않음
- **AI 추천 보완:** 필수/선호 조건, 가격 구분, 사실 기반 추천 이유 규칙 명시
- **방문 가이드 보완:** 공연별 입장 시간·관람 방식·예매/현장가·영어 안내를 구조화
- **포스터 등록 보완:** 공연장 DB 자동 매칭 시도와 실패 시 수동 선택 추가
- **설계 영향 최소화:** 기존 기술 스택·주요 API·디렉터리 유지, 선택 필드 및 `GET /api/venues`만 확장
- **우선순위·검증 보완:** P0 관객 흐름 우선, P1 포스터 등록 시연, 비교 지표 명시
