# AMP frontend

루트 `README.md`의 최신 동작을 기준으로 구현한 React + TypeScript + Vite + Tailwind 프런트엔드입니다.
`AMP_프로토타입.html`의 아이보리 `#FFFFF0`, 검정, 와인 `#79041B`, 둥근 입력·카드, 모바일 탭 구성을 참고했습니다.

## 실행

Node.js 22.12 이상(개발 검증: Node 24), npm을 사용합니다.

```bash
cd frontend
npm ci
npm run dev
```

기본 주소: `http://127.0.0.1:5173`.

```bash
npm run build
npm run test
npm run test:e2e
```

브라우저 테스트는 로컬 Google Chrome(`channel: chrome`)을 사용합니다. Chrome이 없다면 설치하거나 `playwright.config.ts`를 팀의 Chromium 환경에 맞게 변경하세요. Playwright 테스트는 개발 서버를 자동 실행하며 이미 실행 중이면 재사용합니다.

## 이번 구현의 범위

| 경로              | 화면           | 구현한 프런트 동작                                                                                              |
| ----------------- | -------------- | --------------------------------------------------------------------------------------------------------------- |
| `/`               | AI 추천        | 500자 입력, 예시 입력, 필수·선호 필터, 요청 대기·실패·0건·확인 질문·탐색 제한, 최대 3개 추천, 상세 이동         |
| `/events`         | 공연 둘러보기  | 검색어 없이 목록 조회 경계 호출, 지역·날짜·가격·좌석 필터, URL에 필터 유지, 기본 20개/최대 50개 표시, 상세 이동 |
| `/events/:id`     | 상세·방문 준비 | KST 시각, 입장/시작 구분, 가격 종류, 정책 우선순위, 공연장 안내, 번역 표시·원문 보기·미번역 처리                |
| `/admin/register` | 등록           | 실제 파일 선택·미리보기·검사, 수동 입력, 추출 결과 편집, 장소 선택, 원문 확인, 성공·번역 재시도 상태            |
| 기타              | 없는 페이지    | 안내와 홈으로 복귀                                                                                              |

**프런트엔드에는 더미 데이터가 없습니다.** `src/api/client.ts`의 모든 어댑터는 FastAPI 백엔드(`VITE_API_BASE_URL`, 기본 `http://localhost:8000`)에 HTTP로 요청합니다. 백엔드가 꺼져 있거나 AI가 실패하면 오류를 그대로 `ApiError`로 표시하며, 빈 목록이나 가짜 성공으로 숨기지 않습니다.

추천·목록·상세·포스터 추출·등록·번역 재시도는 백엔드 응답을 그대로 표시합니다. 등록 원문/이미지는 브라우저 저장소에 저장하지 않으며, 언어 설정만 저장합니다.

## 백엔드 연결 지점

`src/api/client.ts`가 아래 API에 연결되어 있습니다. `.env.example`의 `VITE_API_BASE_URL`은 API origin이며 `/media/...` 이미지 URL 해석에도 사용됩니다. AI 호출 시간 한도(추천 30초·등록 번역 15초·포스터 40초)보다 길게 클라이언트 시간 제한을 둡니다.

| 어댑터             | API                               | 연결 시 주의                                                    |
| ------------------ | --------------------------------- | --------------------------------------------------------------- |
| `health`           | `GET /api/health`                 | AI 정상 여부로 해석하지 않음                                    |
| `listEvents`       | `GET /api/events`                 | `items[]`는 공연 객체, 목록을 3개로 제한하지 않음               |
| `getEvent`         | `GET /api/events/{id}`            | 원문과 영문·번역 메타데이터를 함께 반환                         |
| `getVenue`         | `GET /api/venues/{id}`            | 장소 기본 규칙은 해당 공연 확정 규칙과 구별                     |
| `listVenues`       | `GET /api/venues`                 | 기존 장소의 실제 ID만 선택                                      |
| `recommend`        | `POST /api/recommend`             | 원문 그대로 전송, AI 선택 순서 유지, `score` 기반 재정렬 없음   |
| `parsePoster`      | `POST /api/posters/parse`         | `FormData`의 `file`, 브라우저가 multipart boundary 설정         |
| `createEvent`      | `POST /api/events`                | 영문·`price_basis`는 전송 금지, 번역 실패라도 201이면 등록 성공 |
| `retryTranslation` | `POST /api/events/{id}/translate` | 요청 본문 없음, 기존 공연 ID만 사용, 공연을 다시 등록하지 않음  |

요청·응답 타입은 `src/types/api.ts`, 원문 등록 요청 구성과 검증은 `src/lib/registration.ts`, 금액·KST·번역 표현은 `src/lib/format.ts`에 있습니다. UI 입력 검증은 서버 검증을 대체하지 않습니다. 등록 API의 관리자 권한과 업로드 검사는 백엔드가 담당합니다. 현재 프런트는 임의로 실제 검증 데이터를 주장하지 않도록 `data_origin=demo`로 제출하게 되어 있습니다.

루트 README의 소개 필드(`price`, `advance_price`, `door_price`)는 상세 API의 wire 필드(`price_krw`, `advance_price_krw`, `door_price_krw`)로 표현했습니다. README에 남아 있는 `venue_name_detected` 표현과 API의 `extracted.venue_name`/`venue_match` 차이는 어댑터 주석에 표시했습니다. 실제 응답이 README의 별칭을 사용한다면 해당 경계에서 정규화하면 됩니다. 서비스 동작은 최신 README를 우선합니다.

## 검증 방식

- TypeScript 검사와 Vite production build.
- 금액 0/null, KST, 번역 원문·상태, 안전한 URL, 등록 원문 검증·가격 계산·서버 전용 필드 제외, 미연결 API에 대한 단위 테스트.
- 모바일(390px)·데스크톱(1280px) 브라우저에서 탐색, 입력 유지, 언어 전환, 확인 질문, 상세, 번역 원문 보기, 등록 검증, 번역 재시도, 파일 검사, 별도 목록을 검증.
- 성공 응답 검증에는 **기존 `docs/API.md`의 JSON 예시를 테스트 안에서만 주입**합니다. 앱의 `src/`에 더미 공연 데이터나 mock API 응답 모듈은 없습니다. 단위 테스트 코드도 앱 엔트리에서 가져오지 않습니다.
- 실제 서버 통합, AI 호출, DB 저장, 관리자 인증은 이번 검증 범위가 아닙니다.

설정 참고: [Vite 공식 가이드](https://vite.dev/guide/), [Tailwind의 Vite 통합](https://tailwindcss.com/docs/installation/using-vite).
